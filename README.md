# Giggleton

The website for the Giggleton collection of Elixir data visualization packages: a blog and
reference pages, styled as a cross-stitch sampler of a village where each package is a
resident. Giggly the hyena keeps the garden plots, Pica the magpie runs the press, and Scales
the chameleon keeps the weights and measures.

It is a Phoenix LiveView app with no database. Posts are Markdown compiled in by
NimblePublisher, and live Giggly demos will mount inside posts.

## Running it

```bash
mix setup
mix phx.server
```

Then open <http://localhost:4000>.

## Writing a post

Add `priv/content/posts/YYYY/MM-DD-slug.md`. The path gives the date and the address
(`/posts/slug`); the front matter gives the rest:

```elixir
%{
  title: "Nice breaks, those",
  description: "One line: the excerpt in lists and the page's meta description.",
  residents: [:scales],
  tags: ["breaks", "log-scales"]
}
---
The body, in Markdown.
```

A misspelt key, an unknown resident or a tag that isn't lowercase-and-hyphens fails the build.

### Charts

A post's charts are drawn by a script named after it, `priv/charts/YYYY-MM-DD-slug.exs`,
which returns a map of chart name to `Giggly.to_svg/2` output. Draw them with:

```bash
mix charts
```

That writes `priv/static/charts/YYYY-MM-DD-slug/<name>.svg`; commit those with the script.
`mix charts --force` redraws everything, for after a Giggly bump. In the post, a chart is an
image alone in its paragraph, with the caption as alt text:

```markdown
![Fig. 1 — Heavier cars go fewer miles per gallon](/charts/2026-11-03-first-stitches/mtcars.svg)
```

Put two or more chart images on consecutive lines of one paragraph to set them side by side
for comparison, each in its own frame with its own caption. The SVG is inlined into the page at
compile time, in the stitched frame. A chart that hasn't
been drawn yet is a compile warning and a placeholder in dev, and fails a prod build.

### Live demos

A live chart is a `Phoenix.LiveComponent` under `GiggletonWeb.Demos`, in
`lib/giggleton_web/demos/`, that draws with Giggly and renders in `<.demo_frame>`. A post
mounts one with a marker on a line of its own, between paragraphs:

```markdown
<!-- demo: Bins -->
```

A test fails if a marker names a demo that doesn't exist. The demo also renders on the first
request, so a reader without a socket still sees the chart in its starting state.

## The residents

Each package is a resident, with a page at `/residents/<package>` from
`priv/content/residents/<package>.md` and a 24×24 stitch pattern of the same name in
`priv/patterns/`. The front matter is the card and the plate beside the page:

```elixir
%{
  name: "Scales",
  species: "chameleon",
  vocation: "Keeps the weights, measures and palettes.",
  home: "Weights & measures",
  thread: :green,
  says: "Nice breaks, those. Minor ones too, if you want them.",
  install: ~s({:scales, "~> 0.1"}),
  docs: "https://hexdocs.pm/scales",
  source: "https://github.com/giggleton/scales",
  order: 3
}
---
Scales keeps the village's weights, measures and palettes: the `scales` package, ...
```

The body opens with the full vocation as its lede, then says what they do, then the API.
`docs` can be left out for a package not on Hex. A resident's charts work as a post's do,
from a script named after them, such as `priv/charts/giggly.exs`. A post's `residents` may
name anyone with a page here.

## Pages

Standalone pages, such as About, are `priv/content/pages/<slug>.md`, with a `title` and a
`description` in their front matter. Each needs a route, `live "/<slug>", PageLive, :<slug>`;
a test fails for a page without one.

## Feed and sitemap

`/feed.xml` is an Atom feed of every post. Charts go in as `<img>` tags pointing at the
committed SVGs, and a live demo becomes a line linking to its post, since a feed reader can't
run it. `/sitemap.xml` lists every page. Both use the host in `PHX_HOST` for their addresses.

## Where things are

- `assets/css/tokens.css` is generated by the Giggleton design system from its tokens.
  Replace it whole when the tokens change; don't edit it here.
- `assets/css/stitch.css` is the site's own components, built only from those tokens.
- `priv/patterns/` holds the residents' stitch patterns, one character per stitch.
  `GiggletonWeb.PixelArt` compiles them into SVG.
- Charts are never styled by the site. They keep the colours and fonts of the Giggly theme
  that drew them; the site only draws the stitched frame around them.

## Dependencies

Giggly and Pica come from Hex, and Scales comes with Giggly. Pica is optional in Giggly; the
site lists it so chart scripts can register fonts for Giggly to measure and draw text in. Those
fonts are in `priv/static/fonts/`, which also serves them as web fonts (see its README).

## Deploying

The site runs as a release on one Fly.io machine, the app `giggleton` in the personal
organization, with the settings in `fly.toml`. GitHub Actions
(`.github/workflows/deploy.yml`) tests every push and pull request, and deploys `main` with
`flyctl deploy --remote-only` once its tests pass.

Setting it up, once:

```bash
fly apps create giggleton --org personal
fly secrets set SECRET_KEY_BASE="$(mix phx.gen.secret)" --app giggleton --stage
fly tokens create deploy --app giggleton
```

Save the token as the repository's `FLY_API_TOKEN` Actions secret. The first push to `main`
then deploys. For a domain of the site's own, add it with `fly certs add` and set `PHX_HOST` in
`fly.toml` to it.

To deploy by hand instead, `fly deploy`.
